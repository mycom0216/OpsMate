# OpsMate 요구사항명세서

요구사항 ID와 실제 API 및 수용 조건을 연결한다. 권한 검사와 입력 검증은 화면 숨김 여부에 의존하지 않고 서버에서 수행한다.

## 인증과 접근 제어

세션은 8시간 유효하며 쿠키는 HttpOnly 및 SameSite Strict를 사용한다. HTTPS 직접 연결 시 Secure를 부여한다. 리버스 프록시에서 TLS를 종료할 경우 프록시의 쿠키 정책도 운영자가 점검해야 한다.

IP별 로그인 시도는 1분에 15회로 제한한다. 역할은 admin, operator, viewer만 허용한다. 관리자는 자신의 역할을 직접 바꿀 수 없다. 비밀번호 변경과 역할 변경은 해당 사용자 세션 및 WebSocket을 폐기한다.

수용 조건은 비인증 조회 401, 권한 부족 변경 403, 타 Origin 변경 요청 403, 중복 서버 등록 409다. 초기 계정 비밀번호는 무작위 생성하고 공개 패키지에 넣지 않는다.

## 수집과 장애 감지

지표 본문은 cpu, ram, disk, network_rx, network_tx를 모두 포함하고 각 값은 유한 수치 또는 null이다. 사용률은 0에서 100, 네트워크는 0에서 10의 15제곱 이하 바이트/초다. 수신 JSON은 64KiB 이하이며 로그는 최대 100건·각 4000자다.

CPU 85%, RAM 90%, Disk 90% 이상을 감지한다. 97% 이상이면 critical, 그 미만은 warning이다. ERROR 로그는 LOG 장애로 분류한다. 활성 에이전트의 마지막 수신 또는 등록 후 60초가 경과하면 HEARTBEAT 장애를 생성한다.

같은 서버와 분류의 미해결 장애는 active_key 유일 제약으로 묶는다. 자동 해결은 하지 않으며 담당자가 처리 메모를 작성한다. 상태는 open → acknowledged → resolved 또는 open → resolved다. 해결 후 같은 조건이 다시 감지되면 새로운 장애로 기록한다.

## AI 응답 및 실시간 화면 수용 조건

매뉴얼은 한국어 어절 및 문자 bigram으로 토큰화하고 BM25 점수로 최대 3개를 검색한다. AI 활성화 시 Ollama 임베딩 cosine 순위와 BM25 순위를 RRF로 결합한다. 서로 다른 점수 척도를 직접 더하지 않는다.

모델 출력은 원인 가설, 확인 목록, 대응 목록, 문서 ID 배열의 JSON 스키마로 제한한다. 원인 후보와 확인·대응 항목은 매뉴얼의 구조화 근거에서만 선택하고 서버에서도 허용 집합을 다시 검증한다. 자료에 없는 조치와 인용 ID를 거부한다. 임베딩 실패는 BM25로, 생성 또는 계약 검증 실패는 원문 안내로 대체한다. 검색 근거가 없으면 답변을 보류한다.

WebSocket은 HTTP 세션 인증과 Origin 검사를 통과해야 한다. 화면은 실제·가상 서버 및 장애를 분리한다. 네트워크 최초 샘플이나 OS 미지원 값은 미수집으로 표시한다. 기록된 수치는 가상의 성능 지표로 치환하지 않는다.
